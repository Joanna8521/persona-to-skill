# 実際に使うとどうなるか

この文書は収集と梱包の工程がまだ存在しない時点で書かれています。すでに存在するゲートを正しい位置に配線するためであり、後から無理に取り付けないためです。

## 全体の形

```
A  収集     対象を指定し、公開素材を集め、出典ごとに階層を付ける
B  検証     すべてのゲートを実行。ホールドアウトはコーパス自身から切り出す
C  梱包     全緑の実行結果だけが zip を生み、コーパス指紋を刻む
D  導入     利用者が一度だけ手作業で導入する
E  修正     修正は B に戻る。D に直接戻ることはない
```

## なぜ B が C より前なのか

素直に考えた道筋は検証を最後に置きます。skill を作り、導入し、使い、そして誤帰属していることに気づく。これは逆で、理由は D にあります。**skill の導入は手作業の工程であり、会話の中での導入はその会話の間しか持ちません。** つまり修正のたびに、利用者は再導入の代価を払います。

「利用者が問題に気づくこと」を再検証の起点にしたパイプラインは、**最も高価な工程の後に品質管理を置いている**ことになります。v1.0 の zip は、届いた時点ですでに検証済みでなければなりません。そうでなければ、見落としのたびに利用者が支払います。

したがって E は B に戻ります。**修正されたコーパスは未検証のコーパスです。** 修正そのものがまだ確認されていません。

## 二つのテスト、そしてこれは同じテストではない

再構成は**忠実でありながら無用**でありえます。対象の公開素材がすべて採用の話で、利用者が訊きたいのが価格設定なら、完全に正確な再構成は必要なことを何一つ答えません。そこで B は二つを走らせ、ゲートはそのうち一つだけです。

| | 問いの出どころ | 何を訊くか | 性質 |
|---|---|---|---|
| **忠実度**（`G4-holdout`） | **本人**。公開の場で答えており、抽出から取り置いたもの | 本人の判断を再現しているか | **ゲート**。通らなければ zip は出ない |
| **網羅度** | **利用者**。実際に訊こうとしていること | これは自分の役に立つのか | 報告 |

網羅度がゲートではなく報告である理由は、**素材が薄いことは欠陥ではなく、その対象が公の場で何を語ってきたかという事実**だからです。しかしこれは梱包前に利用者へ訊く価値のある唯一の問いを規定し、その問いの形を変えます。

> 訊きたい八種類の問いのうち、コーパスが答えられるのは五種類です。価格設定、チャネル戦略、人員削減の進め方については、コーパスに何もありません。これらについての素材、たとえば講演の文字起こし、有料ニュースレター、書籍をお持ちなら、アップロードすれば直接この欠落が埋まります。

これは人が動ける依頼です。「何かアップロードしますか」はそうではありません。

## 出典

収集は動画を扱わなければなりません。多くの対象について、公開素材の大半が動画だからです。ショート動画、リール、講演、インタビュー、ポッドキャスト。

### 出所は実測であり、信頼ではない

文字起こしは、話された内容を機械または人が写し取ったものであり、その内容そのものではありません。したがってそれを引用することは、その写しを引用することです。問題はそれがどれだけ重要かであり、その差は非常に大きい。**多くの対象は自分の字幕を実際に確認します。** 字幕は検索と情報保障の重みを担っており、確認されたトラックは散文と同じだけ使えます。

近道は YouTube の `trackKind` を読み、トラックを `ASR` か `standard` と見て `ASR` を弱いものと扱うことです。**それだけに頼ってはいけません。** 自動生成トラックを編集したときに再分類されるのかは、調べた限りどこにも文書化されていません。したがってそのラベルは、人が一行ずつ直したトラックについて「自動」と言っているかもしれず、あるいは何の役にも立たないことを言っているだけかもしれません。

代わりに産物そのものを測ります。

| 指標 | 測り方 |
|---|---|
| 句読点の密度 | 100 文字あたりの文末記号の数 |
| 文頭の大文字化 | 文の開始位置が大文字である割合 |
| キュー分割 | テキストが時間付きの断片として届くかどうか |

**本物の句読点と本物の大文字小文字を備えた文字起こしは、誰かが書いたか確認したものです。** ラベルが何を主張していようと関係ありません。どちらも備えていないものはそうではなく、これもラベルの主張とは関係ありません。

これは同時に、帰結を正しい場所に置きます。句読点のない文字起こしは、**対象の考えについて誠実さが劣るのではなく、アンカーできない**のです。`G2-anchor` は引用を出典と照合しますが、大文字小文字がなく、句読点がなく、聞き取りを誤った流れは、その検査を支えられません。これは**機械的な問題であり、誰かの入念さについての評価ではありません**。

OCR で読み取った焼き込みの画面文字も同じ位置にあり、そのように明記されます。

### キューの結合

人手で書かれた字幕トラックであっても、文ではなく時間で分割されているため、一つの文が複数のキューにまたがることは日常的に起きます。キューは保存前に結合します。ハードラップされた散文と同じ理由です。その背景にある実測は `experiments/g2_realcorpus.py` にあります。折り返し行を結合する前は、折り返し点をまたぐ箇所はすべて照合に失敗していました。

## 導入の工程は直せないので、稀にする

一度だけ手作業で導入すること。これはこのプロジェクトが取り除けない費用です。できるのは、**その費用を繰り返し請求するのをやめること**です。

* すべてのゲートが zip の存在より前に走る。
* zip はコーパス指紋とバージョンを携える。利用者がどのビルドを動かしているか分かる。
* 固定されたコーパスからの再生成は決定的である。したがって一度の修正は一度の再導入で済み、推測の繰り返しにはならない。

## 名前

機械の名前が `persona-to-skill` です。その産物は違います。`<名前>-persona-to-skill` というパッケージ名が宣言しているのは**何が作ったか**です。`<名前>-method` が述べるのは**それが何であるか**で、一覧から選ぶ人が知る必要があるのはそちらです。
