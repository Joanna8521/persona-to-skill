# 實際使用起來是什麼樣子

這份文件寫在蒐集與打包階段還不存在的時候，目的是讓已經存在的閘門被接到對的位置，而不是事後再硬栓上去。

## 形狀

```
A  蒐集     指定對象，收集公開素材，逐筆標記來源分級
B  驗收     所有閘門執行；holdout 從語料自己切出來
C  打包     只有全綠的執行結果才產出 zip，並蓋上語料指紋
D  安裝     使用者手動安裝一次
E  修正     修改回到 B，絕不直接回到 D
```

## 為什麼 B 要在 C 之前

直覺上的路徑會把驗收放在最後：先建好 skill、安裝、使用，然後發現它把話張冠李戴了。這是反過來的，而原因在 D。**安裝 skill 是手動的步驟，而在對話裡安裝只在那次對話有效。** 所以每一次修正都要使用者付出一次重新安裝的代價。

一條以「使用者注意到問題」當作重新驗收觸發條件的管線，等於**把品管放在它最貴的那一步之後**。v1.0 的 zip 必須在送出時就已經驗過。代價是使用者替每一次漏掉的東西付錢。

因此 E 回到 B。**一份修正過的語料是一份未驗證的語料**，修正本身還沒有被檢查過。

## 兩個測試，而它們不是同一個測試

一份重建可以**忠實而無用**。如果對象的公開素材全是在談招募，而使用者想問的是定價，那麼一份完全準確的重建回答不了他需要的任何東西。所以 B 跑兩件事，而其中只有一件是閘門。

| | 題目來自 | 問的是 | 性質 |
|---|---|---|---|
| **忠實度**（`G4-holdout`） | **本人**，公開答過，從抽取中保留下來 | 這是否重現了他的判斷 | **閘門**：不過就沒有 zip |
| **覆蓋度** | **使用者**，從他實際打算問的東西 | 這對我有用嗎 | 報告 |

覆蓋度是報告而不是閘門，因為**語料稀薄不是缺陷，而是「這個對象在公開場合講過什麼」這件事實**。但它決定了打包前唯一值得問使用者的那個問題，並且改變了那個問題的形狀：

> 你想問的八類問題裡，語料能回答五類。關於定價、通路策略、以及他怎麼處理裁員，語料裡什麼都沒有。如果你有他在這些題目上的素材，例如演講逐字稿、付費電子報、或一本書，上傳就能直接補上這個缺口。

那是一個人可以動手處理的請求。「你要不要上傳些東西？」不是。

## 來源

蒐集必須處理影片，因為對很多對象來說，公開素材大部分是影片。短影音、reels、演講、訪談、podcast。

### 出所是量出來的，不是信任來的

一份逐字稿是機器或人對所說內容的轉寫，不是那個東西本身，所以引用它等於引用那份轉寫。問題在於這件事有多重要，而這差異極大：**很多對象確實會檢查自己的字幕**，因為字幕承擔搜尋與無障礙的權重，而一條被審過的字幕軌就跟散文一樣好。

誘人的捷徑是去讀 YouTube 的 `trackKind` 欄位，它會把一條軌標成 `ASR` 或 `standard`，然後把 `ASR` 當成比較弱的。**不要只靠那個。** 修改一條自動產生的軌之後它會不會被重新分類，我們查不到任何文件寫明，所以那個標籤可能對一條被人逐行修過的軌說「自動」，也可能根本什麼有用的都沒說。

改成量產出物本身：

| 訊號 | 怎麼量 |
|---|---|
| 標點密度 | 每一百字裡句末標點的數量 |
| 句首大寫 | 句子起始處大寫的比例 |
| cue 切片 | 文字是否以帶時間的片段抵達 |

**帶著真實標點與真實大小寫的逐字稿，就是被某個人寫過或審過的**，不管它的標籤怎麼聲稱。兩者都沒有的那種就不是，也同樣不管它的標籤怎麼聲稱。

這同時也把後果放在對的位置。一份未標點的逐字稿**不是對本人的想法比較不誠實，而是無法錨定**。`G2-anchor` 要拿引文去核對來源，而一份沒有大小寫、沒有標點、還聽錯字的流水句支撐不起那道檢查。這是**機械上的問題，不是對任何人勤勉程度的評價**。

用 OCR 讀出來的畫面燒字處在同樣的位置，而且會照實標明。

### cue 接合

即使是人工撰寫的字幕軌，也是按時間切片而不是按句子切片的，所以一個句子經常橫跨數個 cue。cue 會在存檔前接合，就跟硬換行的散文一樣。背後的量測在 `experiments/g2_realcorpus.py`：在折行被重新接起來之前，每一段跨過折行點的文字都比對失敗。

## 安裝那一步修不掉，所以要讓它變罕見

手動安裝一次，是這個專案移除不掉的成本。它能做的是**停止重複收取這筆成本**：

* 每一道閘門都跑在 zip 存在之前；
* zip 帶著語料指紋與版本號，所以使用者分得出手上跑的是哪一版；
* 從一份固定的語料重新產生是確定性的，所以一次修正只花一次重新安裝，而不是一輪猜測。

## 命名

那台機器叫 `persona-to-skill`。它的產出不叫這個。一個叫 `<名字>-persona-to-skill` 的包宣告的是**誰做的**；`<名字>-method` 說的是**它是什麼**，而那才是從清單裡挑東西的人需要知道的。
