## これがペルソナ複製器ではない理由

モデルに誰かに「なれ」と指示すると、モデルがもともと得意なものが返ってきます。すなわち**声**です。話す調子、決まり文句、文の形。返ってこないのはその人の判断力です。判断力は、誰も切り抜きにしない部分に宿っているからです。追い込まれた一問、断った案件、死んだ案件の事後検証といった部分です。

そのためペルソナ型のプロンプトが生むのは、**正しく聞こえるが判断は一般的**なアドバイザーです。これが最悪の失敗の形です。声に説得力がありすぎて、確認するのをやめてしまうからです。

このツールは逆に進みます。抽出するのは意思決定のルールであり、なりすましを拒みます。そうすることで、答えの出ない問いが**答えの出ない問いとして読める**ようになり、聞き慣れた調子でなめらかに埋められることがなくなります。

帰結は二つで、この二つが設計の全体です。

1. **本人に帰属させる主張はすべて、出典を名指しし、引用を添える。** そしてその引用はディスクの出典ファイルと一字一句照合されます。「だいたいこういうことを言っていた」では通りません。その一節そのものか、さもなければその主張は出荷されません。

2. **この skill は「一般的なモデルが間違える問い」で採点されます。** 本人が公開の場で答えており、抽出工程が一度も見ていない問いを使い、記録された**ベースライン**で二つのプールに分けます。ベースラインとは、再構成を何も読み込まない状態で同じ問いに答えさせた結果です。

   実務家が公の場で口にすることの大半はコンセンサスです。そして再構成は、何かを学んだかどうかにかかわらず、そうした問いには正しく答えます。一つのプールで採点すると、重要な十問のうち五問正解に四十問のコンセンサス回答を足したものが 90% と読めてしまいます。そこでコンセンサスプールは報告のみでゲートには一切使わず、ゲートが読むのは**乖離プール**です。既定の答えが間違っている問い、すなわち判断力が実際に移植されて初めて正解できる問いです。既定のしきい値はそこで 80%。これは引き算ではなく直接測った**ベースラインからの上積み**です。

   そして誠実な帰結を、ゲートは隠さず述べます。**公開された立場がすべてコンセンサスである対象は、意味のある再構成ができません。**

## 人が本より難しい理由

本を蒸留する作業は、大半が運搬です。著者がすでに知識工学を終えてくれています。フレームワークには名前があり、章には順序があり、事例はそれが支える主張と対応づけられています。

実務家のアウトプットにはその足場がありません。何年にもわたり複数の形式に散らばり、繰り返しが多く、そして自己矛盾しています。2021 年に取っていた立場を、その後に自分で反駁していることもあります。おまけに重みづけが逆です。公開素材の多くはマーケティング用なので、結論を載せて推論を伏せています。

これが抽出の形を決めます。**出典は等価ではありません。**

| 重み | 素材 |
|---|---|
| 高 | 追い込まれたインタビュー、公の場での反論、事後検証、断った案件、敵対的な質問への回答 |
| 低 | 主張記事、宣伝文、引用されやすい一言、講座の目次 |

基調講演とまとめ記事しかないコーパスからは、使える意思決定ルールは一つも出てきません。そしてホールドアウトのゲートは、自信ありげな抜け殻を作る代わりに、そう述べます。

## 何を生成するか

```
reconstructions/<slug>/
├── SKILL.md              意思決定ルール。各主張に出典アンカーつき
├── decision-table.md     状況、まず何を問うか、判断基準、何を断るか
├── refusals.md           どういう条件で断るのか
├── contradictions.md     どこで自己矛盾しているか、何が両立させるか
├── sources.json          出典ごとの階層、日付、取得の出所
└── holdout-report.md     一致率、乖離点、未知のまま残ったもの
```

`refusals.md` がたいてい最も有用です。実務家の肯定的な主張は誰でも言い換えられますが、**どういう条件で断るのかは、ほとんど誰にも当てられません**。指紋のようにふるまうのはその部分です。

`contradictions.md` は、矛盾を問題ではなく**発見**として扱います。2021 年に A と述べ 2024 年に正反対を述べた人が立場を反転させていることは稀です。たいていは**語られていない条件**が変わったのであり、その条件を取り出すことが再構成全体で最も価値のある成果です。本人自身が一度も明示していない判断基準だからです。したがって各項目は「どういう条件なら両方が成り立つのか」に答えなければならず、条件が見つからない項目は未解決のまま印をつけて残します。新しい方を採って先に進むのは、発見を捨てる行為です。

これは副作用として、アドバイザーが対象本人が公に撤回した見解を引用するのを防ぎます。この種のアドバイザーの信用を最速で失わせるのがそれです。

## 出典の階層

**プロジェクト単位ではなく、文書単位で割り当てます。**

| 階層 | 素材 | 取り扱い |
|------|----------|-----------|
| **T0** | 本人から提供された非公開素材 | それを名指しした同意記録が必要 |
| **T1** | 公開かつ自由に引用可能 | 引用し出典を示す |
| **T2** | 公開だが著作権で保護 | 出典を示した短い引用のみ |
| **T3** | ペイウォール内、流出、閉じたコミュニティから取得 | **パイプラインに入れない** |

T3 はしきい値ではなく**カテゴリ**です。いかなる同意記録も、いかなる出力範囲も、これを解除しません。

## 動画、そして文字起こしとは何か

多くの対象について、公開素材の大半は動画です。したがって収集は字幕を扱わなければなりません。これについて二つのことは、仮定ではなく**実測**です。どちらも実在する人手による講演の文字起こし（427 キュー）に対して走らせて初めて分かったことです。

**字幕は文ではなく表示タイミングで区切られています。** その文字起こしでは、文末の句読点で終わるキューは 59% しかありませんでした。つまり**キュー境界をまたぐ引用は五つに二つが `G2-anchor` で落ちます**。しかもその理由は誤引用とは何の関係もありません。保存方法が勝手に作った境界を、引用がまたいでしまっただけです。そこでキューは保存前に結合します。

**文字起こしには他人の言葉が入っています。** 同じ文字起こしは `(Audience) Good.` を本文にそのまま格納していました。話者自身の最初の一文から二キュー後です。区別せずに保存すれば、他人の言葉が本人の言葉として引用可能になります。そして `G2-anchor` はその引用を**正しく通します**。その文字列は本当に出典の中にあるからです。これは**保存方法が生み出した誤帰属**です。

そこで話者の発言区間を検出して印をつけ、その印づけは**未知の側に倒れる**ようにしています。検出は本質的にヒューリスティックであり、そうでありえません。中国語と日本語には大文字小文字がなく、「私が思うに：」は話者ラベルとまったく同じ形をしています。ある区間が本人のものだと言えるのはラベルが本人と一致するときだけ、他人のものだと言えるのはラベルがそう明言しているときだけで、それ以外はすべて未知として人が解決できるよう表に出します。どちらに推測しても損をします。「本人」と推測すれば他人の言葉が本人のものとして引用可能になり、「他人」と推測すれば本人自身の言葉が捨てられます。

**本人以外の発言区間は保持します。汚染ではなく文脈だからです。** 「いつもではありません。」という一文は、その前の問いがなければ何も述べていません。そして**本人が追い込まれている素材は、最も情報量の多い素材です**。したがって本人の各発言区間は、それを引き出したものを記録します。

### アンカー可能性は実測であり、信頼ではない

近道は YouTube の `trackKind` を読み、トラックを `ASR` か `standard` と見て `ASR` を弱いものと扱うことです。**やめてください。** 自動生成トラックを編集したときに再分類されるのかは、調べた限りどこにも文書化されていません。したがってそのラベルは、人が一行ずつ直したトラックについて「自動」と言っている可能性があります。ラベルは記録しますが、何も決定しません。

代わりに**保存されたテキスト自体**を測ります。文末の句読点と文頭の大文字化です。二言語、約 19 万文字の実在する人手によるテキストでは、密度は 100 文字あたり 1.02 から 1.85 の範囲でした。そして同じテキストから句読点を取り除くと、測定値はちょうど 0.00 になります。したがってしきい値は、何も落ちてこない隙間に置かれています。

**これが何を買うのかは正確に述べる必要があります。** 確立するのは**アンカー可能性**です。文の境界があるテキストは引用の照合を支えられますが、句読点のない流れは支えられません。引用の区切りになるものが存在しないからです。**人のレビューを受けたことは確立しません。** 現在の音声認識は自前で句読点を打つからです。`anchorable` を「人が確認した」と読むのは、ここにある以上のものを読み取っています。

## 出力範囲

**軸は一つだけです。スイッチが必要な問いは一つしかないからです。この結果はどこへ行くのか。**

| | `PRIVATE` 自分用 | `PUBLISHED` 外部向け |
|---|---|---|
| 出典階層ゲート | 実行 | 実行 |
| 出典アンカーゲート | 実行 | 実行 |
| ホールドアウトゲート | 実行 | 実行 |
| 開示ブロック | 不要 | **必須** |
| なりすまし表現 | 警告 | **ブロック** |

誰かの公開講演からアドバイザーを作って自分で使うのは、ごく普通のことです。このツールはそれについて説教しません。出典と品質のゲートは変わらず走りますが、**対象を守るためではありません**。ルールを勝手に発明して自信たっぷりに述べるアドバイザーで損をするのは**あなた**です。

**開示が適用されるのは、産物を他人が読むときです。** 第三者が誤解しうるのはその時点だからです。

## やらないこと

* 声の複製、および本人の音声としてのいかなる再現
* 本人を描いた画像、動画、アバター
* 本人が話しているかのように提示される一人称の対話
* 本人が執筆、レビュー、または承認したと示すいかなる主張

**これらはどの範囲でも拒否します。** 2024 年から 2026 年のデジタルレプリカ立法の波（テネシー州 ELVIS Act、ワシントン州 SB 5886、カリフォルニア州 SB 1111、審議中の連邦 NO FAKES Act）が及ぶのは**声と視覚的肖像**です。このツールが生成するのはテキストであり、その線のこちら側に留まります。

## 能力の限界

できないことを提供していると読まれないよう、明記します。

* 同意記録が本物であることは**検証できません**。構造のみを確認します。
* 出典が真正であること、帰属が正しいこと、現行であることは**確認できません**。
* いかなる法域においても、ある用途が合法かどうかは**判断できません**。**法的助言ではありません。**
* 出典が一度も記録していない判断力は**再構成できません**。素材が薄ければ結果も薄く、薄いものとして報告します。
* 対象がビルド後に同意を撤回したことは**検出できません**。

## インストールと実行

```bash
pip install .
```

ドキュメントサイトはこのリポジトリ**から生成**されます。別に書き起こすのでは
ないので、コードから乖離しようがありません。

```bash
pip install -r docs-requirements.txt
python3 tools/build_docs.py && mkdocs serve
```

`docs/` は生成物です。`tools/build_docs.py --check` はページが古くなると失敗し、
CI がそれを実行します。古いページは静かな嘘ではなく、失敗するチェックになります。
リファレンスのページは凍結された契約、ゲートのモジュール、引数パーサから抽出され
ており、それがこれらのページが存在する価値です。

サブコマンドは 5 つ。それぞれ**既に存在し、既にテストされた**関数を包んでいる
だけなので、コマンドラインが加えるのは引数の解析と終了コードだけで、それ以上は
ありません。独自の判断を持つ CLI は 2 つ目の実装であり、2 つは必ず食い違います。

```bash
# この URL は取得してよいか。robots.txt が決め、他は決めません。
persona-to-skill fetch https://example.com/post/1 --robots robots.txt

# インポート契約の形をしたレコードをコーパスディレクトリへ。
persona-to-skill import export.json \
    --subject "ある実務者" --tier T2 --corpus corpus/

# バンドルに対して全ゲートを実行。パッケージ化はしません。CI 向けの形です。
persona-to-skill gates bundle.json --corpus corpus/

# ゲートを通し、全ゲートが通ったときだけ zip を書き出します。
persona-to-skill package bundle.json --corpus corpus/ --out dist/

# ドキュメントの句読点ゲート。
persona-to-skill punct docs/
```

**終了コードこそが、これがコマンドである理由のすべてです。** 0 はゲートを通過、
非ゼロは通過していないことを意味します。判定を表示しておきながら 0 で終了する
ものは、CI ジョブに入れられないゲートであり、それはゲートがないのと同じです。
サブコマンドなしの `persona-to-skill` も非ゼロです。何もせずに成功するコマンドは、
同じ失敗の縮小版だからです。

これは「ゲートのように見えてゲートではないもの」の 4 つ目の形であり、最も純粋な

呼び出しはすべて traceback で終わりました。だから `tests/test_cli.py` があります。
これは `main(argv)` を**呼び出して**終了コードを検証し、import して終わりには

## eval ハーネス

G4 はホールドアウトのスコアが超えるべき基準を定めます。ハーネスが定めるのは、
**記録された観察**が観察として数えられるために何を満たすべきかで、これは別の
問いであり、そのスコアに意味があるかを決めるのはこちらです。

```bash
persona-to-skill eval examples/eval/manifest.json \
    --run examples/eval/run.json \
    --corpus examples/eval/corpus
```

[`examples/eval/`](examples/eval/) に動く例があり、意図的に壊す 9 通りとその
結果の表が付いています。CI はコミットごとにこの例を実行し、そのうち 7 通りを
適用します。誰も実行しない「文書に書かれた挙動」は、誰も実行しないゲートと同じ
形をしているからです。

**ハーネスは観察を生成しません。** manifest（質問と、対象者が実際に言ったこと。
出典に固定されている）と run（再構成の回答、再構成なしのベースラインの回答、
それぞれ一致したか）を読みます。どちらも外部から来ます。自分の質問に自分で
答えるハーネスは自分自身を測っており、その出力はパーセント記号をつけた自己申告
です。

### その数字を実際に守っているフィールド

2 つのフィールドが重みのすべてを担っており、どちらも形式主義ではありません。

`judged_by`。何かが「この回答は対象者の発言と一致する」と判断しました。その判断
は測定であり、したがって計器があります。名前のない計器は検証できません。この
フィールドがない項目は採点されません。

`blind`。**裁定者は、どちらの候補が再構成のものかを知っていてはなりません。**
「こちらが再構成です」と告げられた裁定者は、実験が produce すべきだった答えを
手渡されています。LLM-as-judge はこれに対して人間より強いわけではありません。
非盲検の項目は計上・報告されますが、ゲートには入りません。G4 が抽出時に使われた
素材に与えているのと同じ扱いです。罰ではありません。非盲検の判定は何かの証拠
ですが、これの証拠ではないということです。

### 数えられなくなる 4 通り、分けて記録

| | 意味 |
|---|---|
| run に項目がない | manifest は尋ね、誰も見なかった。分母から外れる |
| 裁定者が未指定 | 計器に名前がなく、判断を検証できない |
| 裁定者が非盲検 | 計上・報告するが、ゲートには入れない |
| 抽出時に使用済み | そこで一致しても何も証明しない |

4 つの異なる欠陥、4 つの異なる修正。項目を増やす、裁定者を指定する、裁定者を
盲検にする、素材を取り置く。1 つの数字にまとめると、ある実行がどれなのかが
隠れます。再構成が薄い質問セットのせいで責められるべきではなく、薄い質問セットが
再構成として通るべきでもありません。

manifest が尋ねていない質問への回答は**ハードエラー**で、警告ではありません。
manifest こそが、対象者の回答が固定されている質問セットです。

### グラウンドトゥルースは先に G2 を通る

eval スイートは「測定している側」であることを理由にゲートを免除されません。
すべての `subject_said` は、数字が 1 つも印字される前にコーパスに対して検査され
ます。しかも G2 を**再利用**し、再実装はしません。2 つ目の引用照合ルーチンは
必ず 1 つ目から乖離し、しかもスイートを書きやすくする方向へ乖離します。

### レポートが示すもの、示すことを拒むもの

divergent プールの数字で始め、consensus の数字をその隣に、ゲート対象外と明記して
並べます。そうしなければ、誰かが見栄えのよい数字をうっかり引用します。`None` は
「not measured」と表示し、0% とは決して表示しません。0% は「測定済みで、悪い」と
読め、それは別の、より悪い主張をうっかりすることになります。

レポートは**自分の計算の整合も取ります**。4 つの「未観察」の理由は、合計と同じ
項目を 2 通りに数えたものです。いつか合わなくなれば、2 つのモジュールのどちらかが
数える対象を変えたということで、その表は完全にもっともらしく見えたまま誤って
います。だからレポートはそれを印字するのではなく、そう述べます。

### 検査できないこと

質問が本当に抽出から取り置かれていたか。ファイルの中にそれを立証できるものは
なく、`seen_in_extraction` は作者自身の申告です。skill がすでに読んでいた素材から
作ったスイートは見事なスコアを出し、そのスコアは何も意味しません。

## ゲート

**五つ。それぞれに、意図的に壊した入力で必ず赤になる負のテストが付いています。** 失敗しえないゲートはゲートがないより悪い。偽の安心を与えるからです。

| ゲート | 何で止めるか |
|------|-----------|
| `G1-consent` | T3 の存在、同意記録のない T0、階層未設定または読めない出典 |
| `G2-anchor` | 引用が出典に存在しない、出典に含まれない数値、出典のない主張 |
| `G3-disclosure` | 外部向けでのなりすまし、不完全な開示ブロック |
| `G4-holdout` | 乖離プールの一致率が 80% 未満、乖離項目が 5 件未満、ベースライン欠落、未観測が 30% 超 |
| `G5-interrogation` | 未回答のメモ欄、出典がないか留保表現を伴う「事実」、決定的な数値が未知のままの確定的判定、未解決の証拠ギャップと矛盾する確信度 |

各ゲートは**独立に再計算**し、依存する入力が欠けていれば **fail closed** し、そして固定の見本ではなく**実際に納品される産物**を読みます。

`G5-interrogation` が存在する理由は、審議で起きる失敗がすべて**なめらかな文章の中に隠れる**からです。出典がないのに既定事実として書かれた主張、誰も検証していない仮定の上に静かに乗っている推奨、「分かりません」と言うべき場所に立っている留保表現。産物が洗練されているほど、この工程が必要になります。規則のうち二つが重みの大半を担います。**それを決める数値が未知である間は、確定的な判定は使えません。** そのとき足りないのは意見ではなく数値だからです。そして**述べられた確信度は、未解決の証拠ギャップと双方向で整合しなければなりません。** 判断に関わるギャップが開いたままの高い確信度は不整合であり、何も欠けていない状態での低い確信度も同じく不整合です。

`G4-holdout` は**未知を一級の状態**として扱います。観測が記録されていない項目は、合格でも不合格でもありません。分母から外れ、別に報告されます。未知の比率が高ければゲートは赤になり、欠陥のある場所、すなわち**問題セット**の責任とします。（Python では `bool` は `int` のサブクラスなので、JSON の `true` は素朴な整数チェックを通過して 1 として合算されてしまいます。このモジュールは誰も記録していないスコアを発明することを拒みます。）
